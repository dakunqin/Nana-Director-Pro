1. 软件能做什么

Nana Director PRO 将项目管理、本地剧本分析、分镜编辑、素材参考、ComfyUI 视频生成和 FFmpeg 成片导出放在同一个工作室中。

典型流程：

创建项目 → 输入或导入剧本 → 本地导演生成分镜 → 人工修改与排序
  → 上传或生成角色/场景参考图 → 检查镜头参数与声音
  → 本地 ComfyUI 生成视频 → 审片与重试 → 本地导出 MP4
  • 剧本与分镜：调用本机 Ollama 中的本地模型，不调用付费大模型 API。
  • 视频：调用本机 ComfyUI 与 H3 工作流。可连接自行安装的兼容 ComfyUI。
  • 素材：支持人物、动物、场景和道具，图片生成需要额外的图片模型。
  • 成片：使用随程序提供的 FFmpeg 处理片段并拼接。
  • 自动化：可选 Agent API；不用 Agent 也可以完成日常操作。

首次获取环境和模型需要网络；下载齐全后，核心创作可以离线进行。若你主动连接局域网设备，推理会发生在该设备，而不是当前电脑。模型有各自的许可，代码开源不代表全部模型可以无条件商用。

2. 准备设备和空间

2.1 平台与硬件

项目说明
桌面发行版Windows 10/11 x64；优先支持 NVIDIA 的托管 ComfyUI 环境
规划模型可以使用 CPU 或 GPU，模型越大，对内存或显存需求越高
视频生成实际可运行性由 GPU、驱动、显存、系统内存、节点和模型共同决定
无独立显卡可以编辑项目、导入分镜、尝试 CPU 剧本规划；不承诺 H3 CPU 生成速度
多张显卡选择具体 GPU；两张卡的显存不会自动合并
Linux/macOS可尝试源码运行核心服务；本版不承诺托管安装和 H3 全流程兼容

软件没有适用于所有机器的“必然出片”显存门槛。顶栏“已就绪”表示基线资源检测通过，不是画质、速度或显存充足的保证。公开验证范围见 验证报告。

2.2 存储空间

  • H3 基础五个模型合计约 57.5 GB（十进制），以模型中心实时显示为准。
  • 还需要 ComfyUI、独立 Python、Ollama、下载压缩包、解压空间和作品空间。
  • 图片模型套件与导演模型另计。若同时使用视频与素材生成，建议准备容量更充足的 SSD。
  • 仅安装基础路线，至少先预留约 80 GB 可用空间；该数值不是所有安装方案的完整容量上限。
  • 便携版运行时也会在 Windows 临时目录解包；数据盘空间充足不代表系统临时目录也充足。

3. 安装、启动和首次准备

3.1 选择安装版或便携版

文件用法
Nana-Director-Pro-0.1.22-x64-setup.exe安装到指定目录，可创建快捷方式
Nana-Director-Pro-0.1.22-x64-portable.exe直接运行，每次启动先解包程序到临时目录
Nana-Director-Pro-0.1.22-source.zip源码，供开发者使用，不是普通用户启动入口
SHA256SUMS-0.1.22.txt发布文件 SHA256 校验值

普通用户不需要预装 Node、Git 或系统 Python。便携版不是“所有数据都写在 EXE 旁边”：默认作品与模型保存在用户数据目录，详见备份章节。

关闭旧版本后再启动新版，不要同时从多个不同版本操作同一个数据目录。

3.2 启动时应该看到什么

  1. 便携版显示“正在启动”的等待图，并解包程序。
  2. 桌面程序显示带动画进度条的小窗口，准备项目数据库和主界面。
  3. 主界面打开，顶栏准备图标继续显示检测中的动画。
  4. 检测完成后，图标变为就绪或提示资源尚需准备。

此时不必反复点击启动图标。ComfyUI 网页不会自动打开；需要时在设置点击相应按钮。

3.3 两种环境接入方式

方式 A：交给软件管理。 适合没有现成环境的新用户。

  1. 打开“设置”，查看显卡、内存和磁盘。
  2. 如需更换数据盘，先选目录，再按提示重启；旧数据不会自动迁移。
  3. 阅读环境与模型许可说明，勾选界面要求的确认项。
  4. 点击安装环境，观察下载、校验、解压、依赖安装和检查的阶段进度。
  5. 安装完成后启动服务。后续只有已安装且明确启用托管的服务才会被自动启动。
  6. 打开“模型中心”，准备导演模型和 H3 基础五模型。
  7. 返回设置，重新检测，按缺失项提示补齐资源。

方式 B：连接已有服务。 适合已经使用 ComfyUI/Ollama 的用户。

  1. 自行启动现有 ComfyUI、Ollama。
  2. 在设置填写地址，常见值为 http://127.0.0.1:8188 和 http://127.0.0.1:11434。
  3. 保存设置，重新检测服务、节点和模型。
  4. 根据缺项安装兼容节点，确认工作流使用的模型名称与实际文件一致。
  5. 如使用外部 ComfyUI，模型必须在它能读取的目录中；复制到 Nana 数据盘不代表外部服务自动能找到。

不要把运行中的重任务反复提交来“测试连接”。先完成资源预检；初次真正生成时，再使用一个短镜头验证实际推理。

3.4 不同任务需要什么

操作主要依赖
编辑剧本、手动分镜桌面程序与本地数据库
自动分析剧本Ollama 服务 + 已下载的兼容导演模型

导出已有视频已成功归档的片段 + 随程序提供的 FFmpeg

4. 认识工作室界面

4.1 顶栏

  • 项目：项目名：显示当前打开的项目，不是磁盘目录名。
  • 性能：显示整机 CPU、内存、GPU、显存占用。三角形条形指示按占用比例填充；它不是仅本软件消耗的统计。
  • 队列：显示当前批次的处理累计耗时，不把所有历史任务或纯等待时间算作本次处理时间。点击进入队列。
  • 准备状态图标：旋转图标表示检测中，警告表示还需准备，勾号表示资源就绪；点击查看设置。
  • 风格选择：随时切换暗色、亮色等界面风格。

主界面顶部固定；滚动工作台不会把顶栏滚走。窗口较小时可最大化，或使用侧栏折叠导航。

完整的“已就绪，可以生成”准备面板只在总览与设置显示；其他页面通过顶栏图标查看状态，避免占用创作空间。

5. 项目与剧本

5.1 新建、选择、重命名

  1. 点击“新建项目”，输入便于辨认的名称。
  2. 创建后进入导演工作台。
  3. 在项目卡片或工作台使用重命名按钮修改名称。
  4. 顶栏同步显示新名称；后续成片下载默认也采用该名称。

每个项目保存独立剧本、设定、分镜、资产绑定和输出记录。切换项目时若有未保存修改，先按提示处理。

5.2 试试示例剧本

总览的“试试示例剧本”会打开已有示例，首次没有示例时才创建。重复点击、重启后再次点击或给示例重命名，不会持续创建新副本。

对早期版本重复创建的示例，本版只合并同名、剧本相同、没有分镜/素材/任务的未使用副本；已修改或已有产物的项目保留，避免误删创作。

5.3 写剧本

在“剧本”页签输入故事。建议明确场景、主体、动作、时间和视觉目标，减少互相矛盾的描述。例如：

第一场：清晨，旧书店。
橘猫从书架后走出，跳上木窗台。暖色阳光照亮它的毛发。

第二场：同一书店，窗边。
穿蓝色外套的女孩走近窗边，看向橘猫。猫缓缓转头。
只保留门铃、脚步和街道环境声，不安排对白。

点击“保存剧本”保存当前项目草稿。编辑剧本、分镜、引用或排序后应主动保存；不要把切换页面当成保存。

5.4 导入剧本

入口位于“剧本 / 项目设定”标题行。

  1. 点击“导入剧本”。
  2. 选择 TXT、Markdown 或 JSON 文件，文件不超过 2 MB。
  3. 预览文本，检查编码和内容。
  4. 勾选确认项，点击“确认导入并保存”。

JSON 可使用 { "script": "这里是剧本正文" }。文本剧本最多 20 万字符。UTF-8 优先，应用也会尝试兼容常见中文编码。导入新剧本不会自动重写旧分镜；是否重新分析由你决定。

可直接试用：示例剧本。

6. 项目设定

在导演工作台点击“项目设定”。这部分控制项目生成参数，修改后保存。

6.1 画面与采样

参数支持值 / 默认值说明
画面比例16:9、9:16、1:1、4:3、3:4、3:2、2:3、21:9横竖屏与超宽屏
分辨率档位0.42、0.5、0.7、0.9、1.0、1.1 MPMP 为像素总量近似档位，不等于固定长边分辨率
采样器dual_clock_euler 默认；另有 euler、euler_ancestral、heun、dpmpp_2m、dpmpp_2m_sde能否运行取决于实际节点/模型兼容性
采样步数默认 4，允许 1–1000 的整数Turbo 路线默认 4 步；更多步数不自动等于更好画质
输出帧率12、15、24、25、30、48、50、60 fps，默认 24H3 原生按 24 fps 生成，其他值由本机转换
视觉风格可编辑文本影响全片视觉描述，尽量保持统一

转换至 60 fps 不会增加模型实际生成的运动细节。提高像素量、时长、模型规模通常会提高资源需求；每次只改一项，便于判断问题。

审片监视器标题区域同步显示画面比例、H3、MP、采样器、步数、帧率、场景数和风格，便于检查当前项目设定。

6.2 场景与资产设定

可以新增场景，编辑名称与描述。场景多时，场景列表内部滚动，添加入口仍可使用。

资产设定描述“这个角色/动物/场景/道具是什么”；素材库绑定图片描述“视频生成时可参照哪张图”。只有文字资产条目、尚无图片时，不能期待参考图模式生效。

7. 生成与编辑分镜

7.1 本地分析剧本

  1. 保存剧本，确认本地导演服务和所选模型已就绪。
  2. 点击“分析剧本 · 生成分镜”。
  3. 等待本地模型处理，在队列或操作记录中查看状态。
  4. 返回工作台，检查场景、角色、动作、时长及引用。

小模型可能遗漏动作、错误拆场或改变角色。自动生成结果是可编辑草稿，必须审阅。长剧本会分段处理；资源不足时可选择更小的本地模型，或在设置采用 CPU 规划。

7.2 手动添加

点击“分镜序列”标题行右侧的加号，添加手动镜头。填写镜头标题、场景、画面提示词、时长和镜头语言。空白视觉提示词不能生成，但可以先排序。

7.3 拖动排序

  • 按住镜头条目或拖动手柄，上下拖到目标镜头上方或下方。
  • 插入位置会显示标记；拖到列表边缘可以滚动列表。
  • 新增镜头可以拖到第一个、中间或最后。
  • 键盘操作：聚焦镜头条目后，按 Alt+↑ / Alt+↓。
  • 排序完成后点击“保存剧本”。

排序保留镜头 ID、内容、资产引用、锁定状态和已有视频，只调整顺序。序号和后续成片顺序随之更新。已提交队列的任务使用自己的快照，不会因编辑草稿而重写。

7.4 镜头语言与锁定

镜头语言选择器按景别、角度、运动等类别提供候选，也可以输入组合描述，例如“中景，低机位，缓慢推近”。候选是对模型的文本引导，不是可精确执行的三维摄影机轨迹。

锁定用于保护已有镜头，后续自动规划尽量保留；它不是禁止你手动修改镜头的权限锁。重新规划前先保存并备份重要版本。

7.5 导入分镜

入口在“分镜序列”标题行。支持完整 JSON 或 CSV，先预览再确认替换。Excel 先另存为 UTF-8 CSV。

推荐 CSV 列：

title,scene,prompt,duration,camera,assets
窗台上的猫,旧书店,一只橘猫坐在阳光中的木窗台上,5,中景 缓慢推近,
女孩走近,旧书店,穿蓝色外套的女孩走到窗边看向橘猫,5,中景 固定镜头,
  • prompt 必填；duration 为 2–15 的整数秒，缺省为 5 秒。
  • 资产引用须匹配当前素材库中的名称或 ID。重名时使用 ID。
  • 多个引用可使用分号分隔；含逗号的 CSV 单元格应使用双引号。
  • 导入将替换对应分镜，生成新的镜头 ID；旧视频文件保留，但不会自动成为新镜头的输出。
  • 完整 JSON 必须包含有效的 summary/assets/scenes/shots 与可解析的引用。

示例：CSV · JSON。

8. 素材库与四视图生成

8.1 上传已有素材

在素材库选择对应资产，上传 PNG、JPEG 或 WebP 参考图，检查名称与资产类型。人物参考图宜清晰展示外观和服装，避免多个主体、遮挡和复杂背景造成歧义。

上传后，在镜头设定中勾选对应引用资产，并选择自动或参考图模式。单纯在素材库放入图片，不代表所有镜头都会自动引用它。

8.2 生成四视图

  1. 先打开一个项目，进入“生成素材”。
  2. 选择素材生成方案与兼容图片模型。
  3. 选择人物、动物、场景或道具。
  4. 输入素材名称和外观描述。
  5. 如需要，上传参考图，或选择素材库中已有参考图。
  6. 选择入库位置：“新增素材”或已有空白资产/替换参考图。
  7. 点击“生成四视图草稿”。
  8. 在按钮下方观察旋转图标和阶段提示。
  9. 完成后检查四个角度，再审核并加入素材库。

图片生成有两条路线：

方案特点
FLUX.2 Klein 4B 参考编辑四角度四个角度分别生成；没有参考图时，先生成正面，再参考它生成其他角度
SDXL 基础兼容一次生成四格草稿，人物朝向和一致性往往较弱，需要更仔细筛选

FLUX 套件需扩散模型、文本编码器和 VAE；不要只下载 H3 视频模型。默认名称可在界面查看，也可选择已安装的兼容模型。

8.3 描述怎么写

  • 人物：年龄范围、发型、脸部特点、服装颜色、鞋子、体型、统一背景。
  • 动物：品种、毛色、花纹位置、体型、眼睛颜色。
  • 场景：建筑结构、空间布局、材质、时间与光照。
  • 道具：形状、材质、颜色、尺寸比例、标志性细节。

中文可填写，必要时补充明确的英文外观描述。参考图是外观和构图引导，不是可靠的身份锁定。四视图不能保证几何一致、精确背面或服装细节完全相同。

8.4 审核、入库、预览和删除

  • 点击图片放大；关闭按钮、Esc 或背景可返回，不需关闭整个软件。
  • 选择合适视图并确认审核后加入素材库；已入库条目不应继续显示为待审核。
  • 可选择显示已入库记录，回看先前草稿。
  • 质量不合适时，调整参考图/描述重新生成，不要将错误四视图直接用于全片。
  • 素材库提供删除入口。删除前核对镜头引用；引用图片缺失时，参考模式会提示补充，已有成片不会因此自动修改。

9. 生成视频与保持一致性

9.1 生成方式

模式适合用途图片条件
自动选择一般首选；镜头引用资产时使用参考图被引用资产需要已绑定图片
参考图模式尽量保持角色、服装、动物或场景外观至少一个有效引用，且图片齐全
首帧图生视频从指定参考画面开始运动有可用引用图；不与尾帧衔接同时启用
文生视频只依据文字构思画面不使用引用图片，容易重新设计人物

选择了资产但仍使用文生视频，模型不会读取那张图。想保持已有角色，请使用自动或参考模式，并确认引用已勾选、图片已绑定。

9.2 单镜头生成

  1. 在分镜序列选择镜头。
  2. 检查提示词、镜头语言、声音、引用、生成方式和项目参数。
  3. 点击“资源预检”，按提示补齐服务、节点或模型。
  4. 必要时点击“查看 ComfyUI 工作流”检查将提交的节点图。
  5. 点击“生成此镜头”。按钮在镜头设定标题行和下方各有一个，功能相同。
  6. 页面留在工作台，滚动到审片监视器，显示排队或运行反馈。
  7. 完成后在监视器播放视频，检查画面、人物、动作和声音。

若按钮为灰色，先查看当前是否忙碌、视觉提示词是否为空、资源是否就绪、引用图片是否缺失，或是否选了冲突的模式。

9.3 批量生成

检查全部分镜后，点击“生成全部镜头”。视频任务按队列执行，避免同时把多个 H3 任务挤入显存。返回导演工作台时，分镜选择会停留在先前镜头，而不是总跳回第一个。

生成过程中修改项目，不会重写已提交任务的参数快照。需要新参数生效时，重新提交相应镜头。

9.4 可选镜头尾帧

勾选“可选镜头尾帧”，将已生成视频的最后一帧作为新镜头的起始画面。

  • 默认“自动：最近的上一镜头”，寻找当前分镜之前最近已完成的镜头。
  • 可以手动选择当前项目中的其他已完成镜头，不限于同场景。
  • 自动选择依赖分镜顺序。调整顺序后先保存。
  • 批量生成以自动衔接为主；前序必须成功并已归档，才有可用尾帧。
  • 源镜头视频必须存在；提取失败会报错，不会无提示地假装已衔接。
  • 首帧图生视频与尾帧衔接都控制起始画面，界面会限制冲突组合。

尾帧提供画面衔接，不保证动作、人物身份、镜头运动和剧情语义自动连续。需要人物一致性时，还要使用稳定的资产参考和描述。

9.5 提高一致性的实际做法

  1. 同一角色使用同一资产 ID 和明确的参考图。
  2. 统一发型、服装、年龄和场景描述，避免各镜头互相矛盾。
  3. 每镜头只安排清楚、可完成的动作，避免短时间内大量切换。
  4. 相邻镜头需要连续画面时使用尾帧；需要重新构图时谨慎使用。
  5. 先审阅一个镜头，确认人物和风格，再提交整批。
  6. 保留满意版本，质量变差时回退描述、模型或参考图，而不是不断增加步数。

10. 声音与提示词

10.1 默认提示词结构

新建、导入、自动规划及普通旧提示词会按以下结构展示：

integrated_multimodal_description: 橘猫坐在木窗台上，暖色晨光照亮毛发，镜头缓慢推近。

overall_soundscape: N/A

non_diegetic_music: N/A
字段含义
integrated_multimodal_description核心画面与多模态描述，必须有有效视觉内容
overall_soundscape环境声、声音氛围与相关要求
non_diegetic_music非画面内来源的配乐描述

N/A 表示未提供这部分描述，不等于强制静音。已有自定义声音/音乐字段会保留，不会重复嵌套模板。镜头语言与参考关系会补充到实际工作流的视觉提示中。

10.2 H3 原生声音

默认选择 H3 原生声音。视频模型可能主动生成环境声、音乐甚至近似语言的人声，即使你没有安排独立配音。这可能听起来像方言或不清楚的语言。

在“声音描述”可尝试填写：

只有轻微风声、脚步声和门铃声。无对白、无旁白、无人声、无背景音乐。

这是生成引导，不是严格的语音合成控制，不保证语言、口型或台词准确。

10.3 确定不要声音

将镜头的“声音输出”改为 无声输出，保存并重新生成。无声模式不写入模型音轨，适合后期统一配音/配乐。

已有明确保存的无声设置会保留。切换声音设置不会改写已经生成的视频；旧片段仍保留原来的声音。

11. 队列、审片和工作流

11.1 任务状态

状态意义与处理
等待/排队已接受，等待处理；不等于 GPU 正在运行
预检检查环境、节点、模型和参考资源
提交中/已提交工作流正在送往或已进入 ComfyUI
运行中后端正在执行；显示动画图标
收集中下载并归档输出与相关文件
已完成结果已保存；可以播放和下载
失败查看错误、工作流和日志，补齐原因后重试
取消/中断根据任务阶段处理；不要盲目重复提交

每个任务可以查看耗时。等待时长与处理时长不是一回事；顶栏队列时间用于当前批次概览。左侧队列入口在有正在处理的任务时显示动画。

11.2 查看 ComfyUI 工作流

工作台的工作流按钮提供提交前预览。队列中每个任务的工作流按钮提供该任务保存的图或快照预览。

  • 任务实际图与当前编辑草稿可能不同，因为队列保存的是提交时快照。
  • 可检查模型文件名、提示词、参考图、采样器、步数和音轨连接。
  • 需要进入 ComfyUI 网页时，在设置点击打开按钮；程序不会自动弹出该网页。
  • 应用支持的生成路线仍是其内置工作流；导入任意模型不代表可以自动执行任意社区节点图。

11.3 取消与关闭

取消排队中的任务通常可以阻止其继续提交。对已经提交到共享 ComfyUI 的任务，软件不会为了取消当前项目而全局中断其他用户的计算；可能继续查收和归档已有结果。

运行中关闭主窗口时，按提示选择后台继续、等待完成后退出或返回工作室。需要停止服务时在设置操作；软件只管理自己启动的服务，不会接管或终止你独立启动的外部 ComfyUI。

12. 导出成片

12.1 导出前检查

  • 各分镜的顺序正确且已保存。
  • 需要导出的镜头已有成功归档的视频。
  • 不满意的片段已重新生成并审片。
  • 明确是否允许导出部分已完成镜头。

12.2 操作步骤

  1. 在导演工作台点击“导出成片”。
  2. 页面保留在工作台，滚动到成片导出结果区域。
  3. 查看逐镜头处理、合并与保存进度。
  4. 完成后点击“下载成片”。

文件默认名为 当前项目名.mp4，支持中文，会自动处理 Windows 文件名非法字符。历史 film.mp4 输出下载时也采用当前项目名称。浏览器已有同名文件时可能添加数字后缀。

默认严格导出需要各镜头有可用结果。选择允许部分导出时，只拼接已完成的镜头；缺失内容不会自动补拍。应用按分镜顺序处理，通常选择各镜头最近的成功结果；导出前通过监视器核对当前采用的视频。

FFmpeg 会规范化片段参数；无声音片段可补齐静音音轨，便于与有声片段拼接。其他输出帧率按本机转换处理，不代表重新生成运动细节。

12.3 没有反应时看哪里

  • 工作台的“成片导出结果”显示阶段、错误或下载链接。
  • 队列顶部的操作记录也能查看导出状态。
  • 若显示已完成但没出现保存对话框，主动点击“下载成片”，检查浏览器下载列表和默认下载目录。
  • 导出产物位于项目 outputs/export-<操作ID>/ 中。以程序记录的相对路径为准。

13. 模型中心

13.1 内置模型下载

  1. 选择导演、视频或图片模型类别。
  2. 查看文件大小、来源和许可。
  3. 完成所需许可确认后点击下载。
  4. 观察进度，可暂停后恢复。
  5. 下载后会检查文件，校验通过才可正常使用。

断网、下载中断或程序重启后，按界面提示恢复，不要手工把 .part 临时文件改成正式模型名。下载文件存在不代表完整，SHA256 校验才是重要依据。

H3 基础路线包括主模型、Qwen3-VL 文本编码器、视频 VAE、音频 VAE 和 Turbo LoRA。具体文件名见模型中心；模型名相近也不代表可替换。

13.2 已有模型与外部环境

  • 可按界面显示的路径放入已有文件，再触发校验/检测。
  • 托管环境会读取数据盘中的共享模型。
  • 外部 ComfyUI 需要自行将对应目录加入模型搜索路径，或将文件放入该环境标准目录。
  • 增加文件或修改共享目录后，重启 ComfyUI 并重新检测。
  • 资源来源受许可或访问限制时，可在来源网站完成授权后手动下载；本版没有通用的网页登录令牌导入功能。

13.3 添加自己的模型

“添加自己的模型”支持选择本地文件并导入数据盘，类别包括 Checkpoint、扩散/视频模型、文本编码器、VAE、LoRA、视觉编码器、ControlNet、Embedding、音频编码器和放大模型。

支持扩展名以界面为准，包括 .safetensors/.ckpt/.pt/.pth/.gguf/.bin。文件导入属于存储与登记，不会自动修改 H3 工作流或让不兼容模型变得兼容。

自定义导演模型可输入 Ollama 标签并下载。只使用本地推理，禁止 cloud 标签；模型还需具备可用的结构化规划能力。

14. 设置、外观和关于

14.1 服务控制与日志

设置可以查看硬件和数据盘，安装托管环境、启动/停止托管服务，填写现有 Ollama/ComfyUI 地址，选择 GPU 和导演模型。

服务检测会在后台持续进行，首次检测或手动重新检测时显示等待提示，不会一开始就将“尚未完成检测”当作“没有安装”。实际缺失项会提示对应操作。

“运行日志与诊断”可以切换 ComfyUI/Ollama 等日志。报告问题时提供操作步骤和已脱敏错误；不要公开令牌、私人剧本或不必要的个人路径。

14.2 语言与风格

首次默认跟随系统语言。可手动选择简体中文、繁体中文、英语、日语、韩语、西班牙语。语言包本地提供，切换不翻译用户剧本。

六种风格：暗色森林、午夜蓝、亮色暖灰、极简白、石墨黑、磨砂玻璃。顶栏与设置中的选择同步并记住当前设备偏好。

14.3 Agent 接口

普通创作保持默认关闭即可。需要本地自动化时：

  1. 设置 → Agent 扩展接口。
  2. 启用 Agent API，选择是否允许写入和提交任务。
  3. 生成独立令牌，复制到你的本地自动化程序，保存设置。
  4. 先查询 /api/v1/agent/capabilities。

令牌与界面会话令牌分开；重置后旧令牌不再有效。端口随桌面实例变化，不要将示例开发端口当成每次桌面启动的固定端口。详细请求、版本冲突和幂等规则见 Agent 文档 与 OpenAPI。

14.4 关于与捐赠

左下角“关于”提供版本、作者邮箱、开源声明及 PayPal、微信捐赠二维码。点击二维码可放大，关闭按钮或 Esc 返回。

捐赠自愿，不是软件解锁、模型许可证、远程 API 服务或技术支持合同。扫码与确认支付由你在对应支付应用中完成。

15. 备份、迁移和升级

15.1 默认数据位置

Windows 桌面版默认：

%APPDATA%\Nana Director PRO\StudioData

若已在设置选择其他数据盘，以设置显示的实际目录为准。开发模式默认使用项目 data/，也可通过环境变量指定。

StudioData/
├─ studio.sqlite              项目、设置、下载和任务记录
├─ projects/<项目ID>/assets/   上传与生成素材
├─ projects/<项目ID>/outputs/  片段、工作流、尾帧和成片
├─ models/                    共享模型
├─ runtime/                   托管独立环境
├─ packages/                  下载与校验后的安装包
├─ backups/                   项目 ZIP
└─ logs/                      日志与诊断

15.2 项目备份与完整备份

  • 项目 ZIP：使用界面备份项目，包含项目数据、任务清单、素材和视频；不包含模型或系统运行环境。
  • 完整备份：退出软件，确认托管服务和任务已停止，再复制整个实际数据目录。数据库可能使用 WAL 文件，关闭后完整复制比只拷贝 studio.sqlite 更可靠。
  • 本版没有承诺一键导入任意项目备份 ZIP；备份可用于保存产物、人工恢复和后续迁移。

15.3 换数据盘

  1. 先备份旧数据，退出任务与服务。
  2. 在设置选择新目录并退出程序。
  3. 如需保留原作品，将旧数据目录的完整内容复制到新目录，保持结构。
  4. 重启后检查项目、素材、模型与服务路径。
  5. 迁移确认前保留旧目录备份。

选择新目录只是改变下一次使用的位置，软件不会自动移动旧文件。外部服务模型目录需要另外核对。

15.4 升级

下载新版发布包，核对文件，退出旧版后运行。保持原数据配置可继续使用已有项目。不要在安装目录或便携解包临时目录中手工存放唯一一份作品。

16. 完整实操示例

目标：制作一段“书店里的橘猫与女孩”短片，全部在本机处理。

  1. 启动软件，等待检测结束；根据提示准备导演模型、H3 和服务。
  2. 点击“试试示例剧本”，或创建“书店清晨”项目并导入示例剧本。
  3. 项目设定选择 16:9、0.5 MP、默认采样器、4 步、24 fps，保存。
  4. 自动分析剧本；若暂时没有导演模型，可以导入示例 CSV 或手动创建镜头。
  5. 将分镜整理为“橘猫出场 → 女孩走近 → 对视”，必要时上下拖动，保存。
  6. 在素材库为猫和女孩绑定清晰参考图，或在生成素材页面分别生成并审核入库。
  7. 为相关镜头勾选资产，选择自动或参考图模式。
  8. 不需要人声时，明确选择无声输出；需要环境声时采用原生声音并写明要求。
  9. 先生成第一个 5 秒镜头；确认人物、动作与声音后再继续。
  10. 需要画面连续时，下一镜头勾选可选尾帧，默认最近上一镜头，或手动选来源。
  11. 查看队列和实际工作流，等待结果归档；回到监视器逐镜审片。
  12. 调整不满意的镜头并重新生成。
  13. 保存顺序，点击导出成片，完成后下载 书店清晨.mp4。
  14. 对项目执行备份；重要作品另做完整数据盘备份。

此示例是操作路线，不承诺特定设备的耗时或模型的最终画质。

18. 当前边界与术语

  • 本版是开源预览版，自动化和桌面工具测试通过不等于所有 GPU 上的实际 H3 出片验证。
  • 上传任意模型不等于任意工作流自动适配；内置 H3 视频路线、FLUX 与 SDXL 素材路线各有对应要求。
  • 四视图、参考图、尾帧和文字引导提高可控性，但不构成严格的人物身份锁、三维重建或稳定配音系统。
  • 本版没有承诺专业剪辑时间线、精确转场、口型同步、独立 TTS、自动字幕或任意成片工程导入。
  • “就绪”是资源检测；“已完成”是任务归档；“审片通过”是用户对实际结果的判断，三者不同。
  • Seed 为随机种子，MP 为像素总量档位，VAE 为模型编解码组件，LoRA 为模型附加权重，Checkpoint 为整合模型文件类别。
