# 首版验证报告

日期：2026-10-31。版本：0.1.0 开发预览。此报告区分程序验证与真实模型生成，不把模拟服务测试视为真实出片。

## 已验证

最终自动化检查：39 项 Node 核心/集成测试、6 项浏览器流程测试通过。Windows 打包后应用的窗口、本地服务、隔离 preload、FFmpeg 与 7-Zip 可执行文件均通过实际启动检查。

- Node 服务与 SQLite：项目持久化、版本冲突、路径约束、来源与令牌检查。
- 本地导演协议：结构校验、重复/悬空 ID、合法时长、分段覆盖、有限修复、锁定镜头保留、拒绝云模型。
- 模型下载：真实本机 HTTP 服务器测试 Range 续传、服务器忽略 Range、校验失败、重启暂停与磁盘不足门禁。
- H3 图构建：五个基础模型的精确文件名、种子、参考图、缺节点/模型门禁。
- 队列：幂等提交、已知 prompt_id 历史恢复、输出归档、共享实例不全局中断。
- 浏览器：项目创建、剧本保存后刷新恢复、模型中心/设置导航、390px 小屏导航。
- Electron：真实窗口、本机服务、隔离 preload 与正常退出。
- 日常启动：仅在用户已安装并明确选择托管的情况下自动启动服务；不接管未授权的外部进程。
- 资源 URL：清单中的 10 个固定模型、环境和节点地址均于本次检查返回 HTTP 200。HEAD 可用不等于完整文件和推理已验证。

## 实际模型与环境测试

- 本机已有 Ollama `qwen3:14b` 实际请求遇到 GPU 显存不足，CPU 重试也因可用内存不足失败；独立服务 `qwen3:4b` CPU 加载同样受资源限制。已补充 CPU 降级和更小模型选项，未把失败测试记作通过。
- 独立 Ollama + `qwen3:1.7b` 在 CPU 上实际完成剧本结构化规划：约 81.8 秒，4 场景、4 镜头、3 资产。格式与引用校验通过；人工检查发现轻量模型仍可能过度拆场景或改写动作，因此这不是剧本忠实度/成片质量保证，必须审片。支持手动修改镜头、资产分类和场景。`0.6b` 只用于兼容测试，不推荐正式规划。
- 真实下载官方 ComfyUI 0.43.0 与 Ollama 0.40.13，固定节点压缩包均校验后解压，并实际执行节点依赖安装。
- 独立 ComfyUI CPU 模式实际启动成功，`object_info` 返回 2037 个节点，基础 H3 图所需类名全部存在。首次遇到资源压力和导入错误，限制后台计算线程后分开验证通过。
- 候选环境的 Ollama + ComfyUI + 必需节点联合健康检查实际通过一次；随后重复压力检查遇到 Windows `WinError 1450` 系统资源不足而失败，安装器按预期拒绝切换，旧环境记录仍保留。当前机器高负载下不能保证连续启动成功。
- 官方 H3 视频 VAE（5,207,808,496 字节）通过应用下载器实际下载完成，SHA256 与固定资源清单一致。真实测试发现 HF 新 CDN 域名未放行，已修复并添加仿冒域名拦截测试。
- 真实 H3 五秒视频生成：尚未验证。没有记录兼容通过的 GPU 档位。没有为此擅自停止用户已有 GPU 任务。
- 构建压力测试发现系统 Node 26、PE 资源编辑、7-Zip 高压缩与 FFmpeg 默认多线程均可能在当前高负载机器上耗尽资源。开发验证改用 Node 24 LTS，发行包使用普通应用目录和低内存打包，媒体导出限制线程。FFmpeg 的真实静音补轨/拼接测试修复后通过。

## 发布边界

源码和桌面构建用于预览和集成测试；在以下验证完成前，不声称生产可用或任意硬件一键出片：

1. 无开发环境的干净 Windows 机器安装验证。
2. 更高质量本地导演模型的剧本覆盖、人物一致性和长剧本测试（1.7B 短剧本结构化调用已通过）。
3. 固定环境/节点/五模型生成五秒视频、可播放并归档。
4. 多镜头关系帧与最终导出在真实生成素材上验证。
5. 打包产物的第三方许可证与对应源码材料检查。

开发机 GPU 为 16GB + 8GB NVIDIA，测试时主卡显存已有大量占用。没有终止其他用户进程，也没有将两卡视为合并显存。
